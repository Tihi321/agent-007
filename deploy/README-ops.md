# agent-007 operator guide (Windows)

Everything here is copy-pasteable. Run the PowerShell blocks in an **elevated** PowerShell unless it says otherwise.
The task paths are `\agent-007\agent` (the agent) and `\agent-007\strata` (the Strata model runner, only when the runner is Strata).
`<controlDir>` is `paths.controlDir` in `C:\ProgramData\agent-007\config\config.json`; the default is
`C:\Users\agent007\AppData\Local\agent-007\control`.

## Install order (each script supports `-WhatIf`; try it first)

```powershell
cd C:\projects\Personal\agent-007\deploy
.\setup-agent-user.ps1 -WhatIf          # S7.1  create the low-privilege user (no password is printed)
.\setup-agent-user.ps1
.\grant-folder-acls.ps1 -WhatIf         # S7.2  needs config.json (copy config\config.example.json and edit it first)
.\grant-folder-acls.ps1
.\new-secrets.ps1 -Runner lmstudio      # S7.4  YOU type the tokens (hidden). With Strata: -Runner strata

.\deploy-app.ps1
.\register-task.ps1 -WhatIf             # S7.6
.\register-task.ps1
.\check-acl.ps1                         # S7.3  read-only, exit 0 means compliant
```

Only if Strata is the 24/7 runner (S7.9; it refuses unless `D:\Strata` is at the pinned commit with a clean tree):

```powershell
.\register-strata-task.ps1 -WhatIf
.\register-strata-task.ps1
```

## Kill switches (S7.8)

Stop the whole agent (it stays stopped; the repeating trigger is disabled too):

```powershell
Stop-ScheduledTask    -TaskPath '\agent-007\' -TaskName 'agent'
Disable-ScheduledTask -TaskPath '\agent-007\' -TaskName 'agent'
Get-Process node -IncludeUserName -ErrorAction SilentlyContinue | Where-Object UserName -like '*\agent007'   # expect nothing
```

Bring it back:

```powershell
Enable-ScheduledTask -TaskPath '\agent-007\' -TaskName 'agent'
Start-ScheduledTask  -TaskPath '\agent-007\' -TaskName 'agent'
```

Disable only the shell tool (the next shell request answers "disabled" without an approval prompt):

```powershell
$controlDir = 'C:\Users\agent007\AppData\Local\agent-007\control'   # use paths.controlDir from config.json
New-Item -ItemType File -Path (Join-Path $controlDir 'shell-disabled') -Force
```

Re-enable the shell (local only: Telegram can never do this):

```powershell
Remove-Item -LiteralPath (Join-Path $controlDir 'shell-disabled')
```

If Strata is the runner, stop or start the model, for example to free the GPU pool for LM Studio. The agent keeps accepting
messages and queues them while the model is down:

```powershell
Stop-ScheduledTask  -TaskPath '\agent-007\' -TaskName 'strata'
Start-ScheduledTask -TaskPath '\agent-007\' -TaskName 'strata'
```

## Uninstall (S7.7)

```powershell
.\uninstall.ps1 -WhatIf              # lists tasks, ACEs and folders
.\uninstall.ps1                      # keeps the data and the user
.\uninstall.ps1 -RemoveUser -RemoveData
```

The uninstaller never deletes, writes or modifies anything under `D:\Strata` or `D:\Strata-data`: it only removes the
agent user's ACEs there.

## Notes

- **Secrets.** `new-secrets.ps1` prompts without echo, never prints a value and sets the file's ACL before writing. The
  Strata key is generated by the script; `register-strata-task.ps1` copies it into the Strata config copy
  (`C:\ProgramData\agent-007\strata\strata.json`), which is a secret file with the same ACL.
- **NTFS is a backstop.** The in-process path policy is the main control. Only user-data paths (`~\.lmstudio` and
  `folders.deny`) get an NTFS Deny Read ACE. `C:\ProgramData\agent-007\`, the agent data root, `D:\Strata` and
  `D:\Strata-data` never do, because the agent and the Strata task must read them.
- **ProgramData root.** The scripts do not change the ACL of `C:\ProgramData\agent-007\` itself; `check-acl.ps1` reports
  ambient `Users` rights on it and on drive roots. Review them.
- **Edit `config.json`** only from an elevated shell: the agent user has read-only access to it.

## Extra bots (Phase 4, S20)

A one-bot install needs nothing from this section. Every extra bot has its own Telegram token, its own memory and its own
folders under `<agent data>\bots\<id>\`; the bots are defined in the settings UI (`security.json`), never in `config.json`.

1. **Create each bot in Telegram (you do this; no script and no agent ever sees BotFather).** In @BotFather: `/newbot`,
   then `/setjoingroups` and choose the bot, then Disable, and leave **Bot-to-Bot Communication Mode off** (the default).
   The optional mirror (bot room) bot is the one exception to Disable: you add it to your private room yourself, and its
   Bot-to-Bot mode stays off too.
2. **Store the tokens.** Elevated: `deploy\new-secrets.ps1 -WhatIf -Bots research,ops -Mirror`, read it, then run it for real.
   It prompts for each token without echo (Enter keeps a stored one), refuses a token two bots share, and sets the secrets
   file ACL before writing anything. Tokens go to `botTokens.<id>` and `mirrorBotToken`. The proxy key is copied by you later (S23.1).
3. **Move `main` into its own folder** (once): stop the agent, then as the agent user
   `node dist\scripts\migrate-bots.js --config <config.json>` (dry run), then with `--apply`. It copies the old `state\`,
   `memory\`, `workspace\` and `prefs\` into `bots\main\` after a backup of the SQLite files and leaves the old ones in place;
   delete them yourself when you are satisfied. It prints the `bots.main` block to enter in the settings UI.
4. **Shared facts and skills** (optional): put `FACTS.md` and a `skills\` folder in `C:\ProgramData\agent-007\shared\`. Only
   you or an admin may write there: give the agent user read only (the `config\` pattern). `check-acl.ps1` reports a
   `shared\` folder, `FACTS.md` or `shared\skills` that the agent user can write as a VIOLATION.
