Date of survey: 2026-10-26. Method: GitHub REST API (stars, license, pushed_at, latest release), project READMEs and docs, plus secondary blogs where marked. Nothing was installed or run.
Legend: [V] verified from a primary source (repo, official docs, GitHub API). [S] secondary source only (blog, aggregator). [U] unverified or conflicting.

Stars are as of 2026-10-26 from `api.github.com/repos/<owner>/<repo>`.

## 2. Reading the table

- "Local model works" and "agent works well with that local model" are different. Every agent below needs reliable tool calling. OpenClaw's own docs say a model that answers a short prompt may fail a real agent turn because of prompt and tool-schema size, and recommend the largest model your hardware can run [V] https://docs.openclaw.ai/gateway/local-models . Goose says models without tool calling can only chat [V] https://goose-docs.ai/docs/getting-started/providers . Plan on a model with native tool-use support and at least 32k to 64k context.
- LM Studio headless: all OpenAI-compatible clients above use `http://localhost:1234/v1`; the Anthropic-compatible route is `POST /v1/messages` (LM Studio 0.4.1+) [V] https://lmstudio.ai/docs/developer/anthropic-compat . Enable "Require Authentication" if anything other than localhost can reach it [V] https://lmstudio.ai/docs/integrations/claude-code .
- Nothing here removes the Telegram cloud hop: messages and files pass through Telegram's servers even if the model is local (general fact, no source needed).

## 3. Top 3 for this user (Windows 11, local LM Studio model, Telegram, system access, memory)

### 1. nanobot (HKUDS)
Best fit on paper. Python, MIT, 49k stars, actively released (v0.3.5, last push today). It has a native `lm_studio` provider preset pointing at `http://localhost:1234/v1`, a built-in Telegram channel with `allowFrom` plus pairing, shell and file tools with `restrictToWorkspace` and exec sandbox options, markdown-based memory (`USER.md`, `MEMORY.md`, "Dream" consolidation), and cron automations. Windows x64 wheels and a PowerShell installer are first-class, so no Docker or WSL is needed. Footprint is small enough to read and audit. Cautions: 0.x version, the shell sandbox does not restrict network, I could not confirm what an empty Telegram `allowFrom` does (so always set your numeric id), and the exec sandbox's Windows behavior is unverified. Sources: https://github.com/HKUDS/nanobot , https://raw.githubusercontent.com/HKUDS/nanobot/main/docs/providers.md , https://raw.githubusercontent.com/HKUDS/nanobot/main/docs/chat-apps.md , https://raw.githubusercontent.com/HKUDS/nanobot/main/docs/configuration.md

### 2. OpenClaw (hardened) , if you want the full-featured assistant
The reference implementation: official grammY Telegram channel, documented LM Studio setup, native Windows Hub/CLI, file-based memory with semantic search, cron plus proactive check-ins, exec approvals with allowlists, and an `openclaw security audit` command. It is also by far the biggest attack surface: 393k stars, a very large codebase, a 2026 RCE CVE (one-click, patched in 2026.1.29 per secondary sources) and hundreds of malicious ClawHub skills [S] https://www.bitdoze.com/openclaw-security-guide/ , CSA documenting indirect prompt injection and link-preview exfiltration [S/V-ish] https://labs.cloudsecurityalliance.org/research/csa-research-note-openclaw-indirect-prompt-injection-2026061/ . Defaults to watch: exec `security=full`, `ask=off` on the gateway host, so you must set `tools.exec.mode` to `allowlist` or `ask` yourself. Choose this only if you commit to: loopback bind, `dmPolicy: allowlist` with your numeric id, no ClawHub skills, exec in `ask` mode. Sources: https://docs.openclaw.ai/channels/telegram , https://docs.openclaw.ai/tools/exec-approvals , https://docs.openclaw.ai/gateway/security

### 3. DIY on Agno (or PydanticAI) with your own Telegram allowlist
If you value a small, readable, fully-yours surface: Agno ships a Telegram interface, memory per user, a scheduler and a documented LM Studio provider; Python, Apache-2.0. Or go thinner with PydanticAI plus grammY (MIT) where the first middleware drops any update whose `from.id` is not yours. You implement the shell/file tools with an explicit allowlist and approval buttons, so there is nothing you did not choose. Cost: you build and maintain tool safety, memory schema and scheduling. Agno's Telegram interface is webhook-based, which means a public HTTPS endpoint or tunnel (adds exposure) [S] ; the grammY/python-telegram-bot route uses long polling and needs no inbound port. Runner-ups: ZeroClaw (Rust, native Windows, `supervised` autonomy default, but Telegram allowlist docs are inconsistent) and Claude Code Channels (best UX and permission relay, but officially requires Anthropic auth, so a fully local model is unconfirmed [U]). NanoClaw has the strongest isolation but needs WSL2 + Docker, and Goose's Telegram gateway is still experimental.

## 4. Security warnings for a chat-reachable agent with shell on a personal PC

1. Telegram identity is the only gate. Allowlist your numeric user id (not username), turn off pairing for strangers after first use, never open group access. A leaked bot token lets someone impersonate the bot, and goose's docs warn exactly that [V] https://goose-docs.ai/docs/experimental/remote-access/telegram-gateway . Rotate via BotFather if it leaks. Keep the token out of repos and chat logs.
2. Indirect prompt injection is the real threat. Anything the agent reads (web pages, emails, files, forwarded Telegram messages, skill descriptions) can carry instructions. CSA documents exfiltration through messaging link previews and poisoning of identity/memory files in OpenClaw [S/V] https://labs.cloudsecurityalliance.org/research/csa-research-note-openclaw-indirect-prompt-injection-2026061/ . Small local models are generally easier to hijack, and OpenClaw's docs state local models lack hosted safety filters [V] https://docs.openclaw.ai/gateway/local-models .
3. Do not give it autonomous shell. Use approval-on-miss or allowlist mode, and route approvals to a channel the injected text cannot reach. Note Claude Code's permission relay lets any allowlisted sender approve tool use [V] https://code.claude.com/docs/en/channels . OpenClaw defaults to full exec with no prompts on the gateway host [V] https://docs.openclaw.ai/tools/exec-approvals .
4. Isolate. Best: run the agent as a separate low-privilege Windows user, or inside a VM/WSL2/Docker with only a work folder mounted (NanoClaw model). Never run under your admin account, never mount your home, browser profiles, SSH keys or password-manager data. Windows has no equivalent of the Landlock/Bubblewrap sandboxes ZeroClaw lists, so assume workspace restriction is advisory on native Windows [U].
5. Third-party skills/plugins are malware vectors. ClawHub saw hundreds of malicious skills (counts vary 341 to 1,184 by source) mostly infostealers [S] https://www.bitdoze.com/openclaw-security-guide/ . Install no skills you did not read.
6. Network exposure. Keep gateways/WebUIs on loopback; one tool's own docs say WebUI access equals admin of the instance (nanobot) [V]. Scans found tens of thousands of exposed OpenClaw instances [S/V] CSA link above. Keep LM Studio's server bound to localhost or require its auth token [V] https://lmstudio.ai/docs/integrations/claude-code . Telegram long polling needs no inbound port; avoid webhooks plus tunnels unless required.
7. Memory poisoning and secrets. Persistent memory files (`MEMORY.md`, `USER.md`) are read back into every prompt, so an injected line persists. Review memory diffs periodically. Don't store secrets in memory or in the same workspace as the agent. Config files hold the bot token in plaintext in most of these tools [V for ZeroClaw https://github.com/zeroclaw-labs/zeroclaw].
8. Supply chain and installers. `curl | sh` and `iwr | iex` installers are common here (OpenClaw, ZeroClaw). Prefer pinned releases, check hashes, and watch for impostor repos: ZeroClaw explicitly warns that only `zeroclaw-labs/zeroclaw` is official [V]; NanoClaw moved orgs (qwibitai to nanocoai) [V], so confirm the current owner. Pin versions, since these projects ship breaking and security-fix releases weekly.
9. Blast radius controls: separate OS user, filesystem allowlist, outbound-network egress filter, no cloud credentials on the box, backups of the workspace, an audit log, a kill switch (stop service) reachable even if Telegram is compromised.
